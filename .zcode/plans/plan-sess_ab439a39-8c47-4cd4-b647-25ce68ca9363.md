## Phase 2 (limited scope): `crates/core` domain layer

Implement the **domain crate only** — the foundation everything else builds on. No protocol adapters, no Tauri bridge, no keychain. This pass produces a fully-tested, dependency-light domain layer that locks in the contract for later phases.

### What gets created

**1. Root `Cargo.toml` (workspace manifest)**
- New file at repo root: defines `[workspace] members = ["crates/*", "apps/desktop/src-tauri"]`
- Note: `apps/desktop/src-tauri` is already a package; the workspace pulls it in. No changes to its existing build.
- Shared `[workspace.package]` (edition 2021, rust-version 1.77, license MIT) and `[workspace.dependencies]` for deps reused across crates.

**2. `crates/core/Cargo.toml`**
- `serde` (derive) — domain types must be serializable for the Tauri bridge later.
- `thiserror` 2.0 — ergonomic domain error enum.
- **No tokio, no async-trait.** Native `async fn` in traits (stable since 1.75; we're on 1.96). One less dep.

**3. `crates/core/src/` — modules**

| File | Contents |
|---|---|
| `lib.rs` | crate root, re-exports public API |
| `protocol.rs` | `Protocol` enum (Ftp, Ftps, Sftp), mirrors TS `Protocol` |
| `credentials.rs` | `Credentials` value object (host/port/user, password as `SecretString`) |
| `connection.rs` | `ConnectionId` (newtype), `Connection`, `ConnectionStatus` — mirrors TS `Connection` |
| `file.rs` | `RemoteFile`, `FileKind`, `FilePath` — mirrors TS `RemoteFile` |
| `transfer.rs` | `TransferId`, `Transfer`, `TransferStatus`, `TransferDirection`, `TransferProgress` |
| `sync.rs` | `SyncDirection`, `SyncDiff`, `DiffReason` — mirrors TS sync types |
| `error.rs` | `CoreError` enum (ConnectionFailed, AuthFailed, NotFound, Permission, Protocol, Io, InvalidPath) via `thiserror`. Maps later to human-readable UI messages. |
| `remote.rs` | **`RemoteFs` trait** — the interchangeable-adapter contract. Uses native `async fn` (no async-trait). Methods: `connect`, `disconnect`, `list`, `stat`, `download`, `upload`, `delete`, `rename`, `mkdir`. Returns `Result<_, CoreError>`. |

**4. `crates/core/tests/` — integration tests**
- Pure domain logic: `RemoteFile` construction, `FilePath` normalization, `TransferProgress` math (percent, remaining bytes), `Credentials` equality.

**5. `crates/core/src/*` — unit tests (`#[cfg(test)]` modules)**
- Each type module gets focused tests (e.g. `protocol.rs` tests enum serde round-trip; `transfer.rs` tests progress calc; `file.rs` tests path join/parent).

**6. Delete the `.gitkeep` placeholders** in crates/core (now has real content). Other crates keep `.gitkeep`.

### Architectural decisions

- **No `async-trait`**: native `async fn in traits` is stable on our toolchain (1.96). Removes a compile-time macro dep. Trade-off: `RemoteFs` can't be used as a trait object (`dyn RemoteFs`) directly — but the Application Layer will hold concrete adapter types behind an enum dispatch, so we don't need `dyn`. This keeps the door open to add `async-trait` later only if dyn-dispatch becomes necessary.
- **`SecretString`** for passwords: type-level marker so a password can't be accidentally logged/serialized. Implemented as a newtype wrapping `String` with a manual `Debug` impl that redacts and no `Serialize` (forces explicit extraction at the keychain boundary).
- **Mirrors the TS domain types exactly** (`lib/types.ts`) so the future Tauri serde bridge is a 1:1 mapping with no translation layer.
- **`RemoteFs::download`/`upload` return a `TransferHandle`** (not a byte stream) — decouples the domain from any particular streaming impl. Progress flows via the transfer crate later.

### Verification gates

Before committing:
1. `cargo check -p flow-core` — compiles clean
2. `cargo clippy -p flow-core -- -D warnings` — zero warnings
3. `cargo test -p flow-core` — all unit + integration tests pass
4. `cargo doc -p flow-core --no-deps` — public API docs build
5. `cargo build` from workspace root — entire workspace (incl. src-tauri) still builds
